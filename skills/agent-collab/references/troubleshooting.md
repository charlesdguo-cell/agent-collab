# Local troubleshooting, no maintainer required

Resolve the actual runtime from the installed Skill symlink. Use its CLI, not a guessed globally installed command. Avoid printing config, auth JSON or full logs.

- **Missing dependencies**: check node >=24, npm, python >=3.9 and codex executable on this computer. Use official distributions, validate downloads and reuse existing login. `doctor` requires configuration first; a missing config means continue setup, not reinstall Node.
- **npm install failed**: the installer uses a temporary staging directory and deletes only its own failed stage. Fix the reported network/proxy/disk issue, then retry once. Preserve existing releases. Never disable TLS verification.
- **Skill conflict**: preserve the user's existing directory/link. Inspect ownership. Choose an intentional different skill directory with `--skill-dir`, and record it; don't delete unrelated skills. Ensure both agent-collab and team-consult are discoverable. Missing discovery can be handled by reading the installed file directly in the current session.
- **Older release**: inspect receipt and service. `--activate-upgrade` now stages an immutable release and schedules a separate maintenance worker for configured macOS services. It waits for running jobs, preserves pending tasks/config/session/SQLite, switches at idle, and rolls back failed activation. Use the actual `--root`, `--state-dir` and `--service-label` for this identity. Read `maintenance-status.json`; queued is not activated. Do not stop yourself mid-task or delete a plist to bypass checks. With the local owner’s explicit authorization, add `--enable-owner-autonomy`; routine upgrades then run without workspace-only restrictions. Old installations whose sandbox cannot write runtime/state need a one-time local terminal bootstrap; do not pretend a group message changed their OS permissions.
- **Pairing fails**: verify the exact bot, private-message scope/event, long connection, published version/availability and setup process. Code expires after ten minutes. A group message cannot pair. Wrong pairing identity requires a new verification, not manually editing owner IDs.
- **Service fails**: `launchctl print gui/$(id -u)/ai.ikigen.agent-collab` checks actual state. Inspect the plist's executable and PATH, then run the same runtime's doctor. A disabled service is an intentional state: identify why before enabling. Existing bot listeners on another computer must stop before this computer starts. Don't start a foreground duplicate to test a running launchd service.
- **No group reply**: confirm configured chat and bot, app published and in group, @mention correct, event subscriptions and group-message scopes. Check local `doctor` plus a bounded redacted error tail. Direct pairing success doesn't prove group permissions. Ask the owner for a real group message when agent tools cannot send as a human; do not spoof sender identity.
- **Replies work but task fails**: check local Codex login and executable/version, authorized project, job state and original session. Do not edit unrelated global Codex policy. With explicit local-owner authorization, `executionMode: owner-autonomy` configures only this bridge’s threads for authorized host operations without an extra Agent Collab risk-confirmation step. Without that opt-in, inherited policy remains. Runtime command/file approvals now go to the owner privately rather than being blanket-declined. If CLI flags are unsupported, compare the installed official Codex help before upgrading. Preserve errors as evidence.
- **Execution uncertain after crash**: inspect produced files and task effects first. Only the owner can authorize resume after reconciliation; never replay blindly. Don't delete the SQLite database to make the warning disappear.

Finish with observed stages and exact next action. User authentication, administrator review, unsupported platform or a genuine defect may prevent full completion; say so plainly. Do not default to asking the maintainer to remotely operate the computer.
