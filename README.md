# Agent Collab — 开发预览版

让本机 Coding Agent 通过飞书话题咨询团队成员，并将决定交回原执行会话。

**当前是 alpha 工程，不是已完成验收的 V1。不要用模拟测试结果替代真实机器人、真实模型、安装和上线验收。**

## 交给你自己电脑上的 Agent 安装

把这句话交给本机 Codex：

> 请读取 https://github.com/charlesdguo-cell/agent-collab/blob/main/INSTALL.md ，按说明安装 Agent Collab，并继续完成机器人配置和群聊验收；不要在下载完成后停止。

公开仓库不需要 GitHub 账号。当前仅 macOS + Codex 进入真实用户验收；不是已完成 V1。

## 运行条件

- Node.js 24+；选择使用的本机 Codex 或 Claude Code 已安装、本人已登录；不要求同时安装两者。
- 独立飞书自建应用机器人，启用长连接消息事件 `im.message.receive_v1`，已加入指定群。
- 必要消息发送、历史读取、群消息接收权限需按飞书管理端实际配置。不要让本程序与另一个服务共享同一个机器人事件连接。
- macOS 后台服务入口已实现但尚待干净机器验收；其他系统可运行内核，尚无已验收的一键后台安装。

## 开发运行

```sh
npm ci
npm test
node cli.mjs setup
node cli.mjs doctor
node cli.mjs start
```

本机配置页将凭据保存到 `~/.agent-collab/config.json`（目录 0700、文件 0600），不向群里发送。支持自动发现机器人身份、私聊一次性配对获取安装者身份，以及从 openChatId 链接识别群。不要将本机配置目录放到 Git、网页或安装包中。`AGENT_COLLAB_HOME` 可用于隔离测试实例。

macOS 可执行 `node cli.mjs install-service` 注册登录后自启动；目前 setup 只保存配置，不自动宣称认证或长连接成功。

## 安装后有哪些 Skill？

- `agent-collab`：本机安装、飞书配置、诊断与验收，附完整操作参考。
- `team-consult`：日常协作；识别当前会话是否受管，指导显式任务交接，或在受管会话中咨询、多轮讨论和确认后续跑。

两者都会安装到 Skill 目录。普通终端会话不会因安装 Skill 自动获得异步唤醒；需要明确交接到新的受管任务，原终端不能同时继续写同一个任务。

当前只实现人与受管 Codex 的咨询闭环。bot 消息会被忽略，任意人/AI之间自由主动互聊仍是未实现目标，不能算已交付。

## 使用

- 群主会话 @自己的机器人：`新任务：实现某个功能`。
- `查看任务` / `/tasks`：安装者查看任务。
- 在咨询话题中正常回复：排队进入绑定的原会话，讨论回合使用只读权限。
- `/approve C-xxxxxxxx 2`：指定负责人确认指定方案版本。
- 咨询话题中 `暂停这个任务` / `取消这个任务`，或 `/pause T-xxxxxxxx` / `/cancel T-xxxxxxxx`。
- 已核对中断结果后，所有者可说 `已核对，继续这个任务` 或 `/resume T-xxxxxxxx`。暂停时保留未确认的咨询；恢复不能跳过它们，取消的任务不能复活。
- 安装者 @机器人可说 `切换项目：/绝对路径`、`改用Claude`、`改用Codex`、`检查连接`，更改仅影响后续任务的项目和 Agent。新增 Agent 仍须先在本机安装并完成本人登录。
- `/role 我负责前端交互`：只更新发送者自己的职责，不能借此获得管理权限。

Agent 通过随会话注入的 `team_consult` MCP 工具发起/修订/查看咨询。MCP 令牌按任务限定、每轮撤销，不出现在命令参数或群消息。CLI 是备用接口，不需要把整个终端交给远程群成员。

## 已实现的机制

SQLite 持久任务、咨询、消息映射、执行队列和 outbox；按 app/chat/root/parent 精确路由；原始消息 ID 去重；版本化确认；同任务串行；取消与迟到回复处理；执行中崩溃标记 uncertain，禁止盲目重放；发送使用固定 UUID，失败最多自动尝试两次；首次介绍去重；明确职责记录来源。

讨论用原 session 的只读回合，最后产生结构化回复和完整方案。方案改变由协调层递增版本，不由普通聊天直接触发代码执行。

## 验收范围与尚未达到的 V1 条件

本次真实验收以 Codex 为准；Claude 适配保留为可选能力，不宣称已验证。

- 真实飞书机器人及测试群端到端、两安装者并行验收。
- 所选运行时的实际登录、MCP 调用、原会话权限切换与三轮讨论验收。
- 自然语言确认目前仍以显式版本指令为准；恢复 uncertain 运行前仍需要所有者核对已发生的操作。
- 已实现群与活跃话题的有界分页补取、去重和缺口标记，仍需真实 API 断线恢复验收；不能把单轮补取成功视为无条件不丢消息。
- macOS 安装脚本已实现校验包、按需安装 Node/Agent、引导本人登录及后台注册，但尚未完成干净机器安装与首次真实收发验收。
- 原生附件处理、任务产物自动发布仍待完成。开发预览包的服务器下载部署另有实际回执，不能代表这些运行时能力已经实现。

## 数据与发布边界

程序不上传项目、聊天、配置或会话历史。服务器应只接收明确选择的交付目录和安装包。npm `files` 白名单限制打包范围；每次发布需核对包内容和 SHA-256。审批意愿不意味着公共发布私有源码/聊天。

## 测试

`npm test` 中明确命名为 simulated 的用例使用内存传输和假 runner，验证状态机而不调用模型。临时 SQLite 测试覆盖重启持久性。真实验收证据应保留在工程 artifacts，不放入分发包。

安装器回归：`python3 -m unittest discover -s test -p "*_test.py"`。包含失败后重试、双 Skill 发现、重复安装、篡改和冲突保护；依赖命令使用模拟替身，另做真实 npm ci 安装冒烟。
