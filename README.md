# Agent Collab — Codex 群协作预览版

让每个人自己的电脑、专属飞书机器人和本机 Codex 连通。直接 @机器人 开始工作，在同一话题反复讨论、咨询和执行；支持实现同一协议的 Agent 之间协作。

## 一句话安装

交给自己电脑上的 Codex：

> 请读取 https://github.com/charlesdguo-cell/agent-collab/blob/main/INSTALL.md ，安装时查询公开仓库最新已发布版本（含预览版，不写死版本号），完成本机 Agent Collab 安装、机器人配置和自动自检，并确认 agent-collab 与 team-consult 两个 Skill 可读；不要停在下载阶段。

公开仓库无需 GitHub 账号。安装者提供专属机器人的 App ID、凭据、群和项目；本机 Agent 主动提供创建机器人和权限配置帮助。本人登录、私聊配对等必要交互在本机完成。发布验收由维护者负责，不交给安装者跑测试脚本。

## 运行条件

- macOS、Node.js 24+、Python 3.9+，本机 Codex CLI 已安装并登录。
- 专属飞书自建应用机器人加入目标群，长连接订阅 `im.message.receive_v1`。
- 发送、历史、群成员读取及 **包含机器人消息** 的接收权限，详见 [配置指引](skills/agent-collab/references/feishu-setup.md)。普通群消息权限不能代替 include-bot 权限。
- 一个机器人只由一个服务接收事件；不能在维护者电脑代跑用户的机器人。

## 使用

- @机器人提出问题或任务；同话题后续回复保持上下文。同事也可参与。
- 机器人复用本机 Codex 配置及登录，按话题建立独立持久 thread；不接管已打开的终端。
- Agent 可使用本机已有工具与授权，不统一限制为只读；实际需要本机批准时报告阻碍，不替人批准或扩大权限。
- 需要别人输入时发出明确请求；最终结论结束该次交流。同一话题仍可开始新问题。结束结论可以恢复本地依赖工作，但不会自动再次 @对方。
- `/role 负责范围` 更新自己的群内分工记录；带来源和更新时间，不能据此获得管理权限或证明 bot 归属。
- 安装者在原话题发送 `暂停这个任务`、`取消这个任务`；核对中断影响后用 `已核对，继续这个任务`。取消不能复活。
- 安装者 @机器人 `查看任务`、`检查连接`、`切换项目：/绝对路径`。项目修改仅影响新话题任务。

## 机制与边界

- 原消息、引用回复和话题映射到任务与 Codex thread；同任务串行，不同话题最多默认 3 个并行。
- 首次进入已有话题时有界补取原文；权限失败明确标注缺口，不拿其他群消息代替。
- 按应用和群隔离的 SQLite 保存消息映射、分工、exchange 和去重记录。首次读取介绍与机器人名录，后续按实际消息被动更新，不轮询分工。
- 飞书 open_id 是调用应用相关的标识，不能跨应用硬比。出站用本应用名录，入站用平台实际 sender 和 mention。
- AI 往返使用 v1 协议，校验指定对象、关联请求、去重、截止时间和轮数。receipt 不调用模型；已结束或迟到的回复不重启旧交流。普通非协议 bot 不自动应答，避免无限回声。
- 旧版本的显式确认咨询仍保留兼容；不是新 Codex 话题的默认审批流程。CLI `task new` 是旧式显式任务交接，不是当前终端续跑。

配置 `~/.agent-collab/config.json`（0600）、状态 `~/.agent-collab/state.sqlite` 留在本机。群绑定分工位于数据库 `group_roles`，由本机 Agent 或群中本人声明更新；已验证安装者绑定来自配置。其他 bot 的负责人关系尚不能仅凭名称自动验证。

## 验证范围

核心路径已在维护者环境用 **两个独立真实飞书 bot + 两个真实本机 Codex thread** 验证：多轮确认、自然结束、同话题第二次提问、各自会话复用，无相互致谢循环。另有状态机、并发、去重、上下文与安装器回归。

这不是两台用户电脑的实装证明，也不是零故障保证。当前仅 Codex 为本轮支持目标；Claude、附件、自动产物发布未完成本轮验收。升级增强、安装断点恢复暂不纳入。现有终端不会自动挂接；需要异步协作时明确交接上下文并停止重叠写入。

## 开发与分发

```sh
npm ci
npm test
python3 -m unittest discover -s test -p '*_test.py'
node cli.mjs setup
node cli.mjs doctor
node cli.mjs start
```

`doctor` 检查登录和 app-server 握手，不调用模型，不把握手当作任务成功。macOS `install-service` 注册后台服务；启动状态不能替代消息闭环证据。

安装器只分发运行白名单，不携带用户配置、聊天或项目。运行时不自动公开项目；模型调用仍使用安装者的 Codex 提供方，群回复经飞书发送。私有验收原始记录不进入公开仓库。

本机 Codex 可通过 `topic start` 主动建立群话题，`topic reply` 续聊，`topic status TASK` 读取结果，`topic members` 获取本应用视角的身份名录。输入格式见安装后的 usage.md。该入口建立独立持久会话，不接管当前终端；讨论结果由当前终端读取后继续使用。
